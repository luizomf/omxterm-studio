# OMXTerm Studio

## Product

A static, browser-only theme and configuration editor for OMXTerm. The theme is the primary workflow; configuration editing is equally available. The site is separate from the desktop application and the OMXTerm Web SSH broker.

## Preview

A large DOM/CSS simulation uses fictional text, fastfetch, htop, ANSI-styled tmux status/dividers, an OMXTerm tab strip, and a snippets sidebar. It does not run commands or use the Restty rendering engine. Normal, bold, dim, background colors, cursor, and selection samples are visible. Bold does not switch ANSI slots. Font rasterization, dim rendering, cell layout, and operating-system chrome can differ from the application.

Tab and sidebar colors follow the desktop's sRGB overlay rules against the fixed `#808090` chrome neutral, scaling overlay alpha with the remaining background tint. Window title/tab visibility follows applied configuration, defaulting to visible. The preview paints the theme background once at `1 - transparency`, with a CSS backdrop blur only when blur is requested and transparency is positive. A viewport-wide local CSS starfield in dark indigo, purple and rose, with mixed-size stars, a small crescent moon, decorative comets and layered mountain silhouettes, provides enough contrast to inspect background effects at low transparency without tinting the terminal's theme colors. The fixed 4px CSS blur is illustrative, not a mapping of the native blur radius. Motion can be paused and is disabled by reduced-motion preferences. This is an illustrative simulation on every target, not a native-effects or platform-fallback prediction. Text, cursor, selection and explicit terminal backgrounds remain opaque. No whole-window opacity or foreground blur is applied. Always-on-top is export-only. The preview supports tabs, sidebar, scene selection, and fullscreen. Its Tabs toolbar toggle can hide demo tabs but cannot override `showTabBar: false` (the toggle is then disabled). These are ephemeral preview controls, not unsupported configuration fields. In the workspace scene, either column can be minimized so the other uses the available width. Persistent-in-view minus/plus controls outside the simulated window restore it even with hidden title/tab bars, with at least one column always visible. Column visibility survives scene switches within the current page, but is neither persisted nor exported. The sky and its motion control are also preview-only, neither persisted nor exported.

The terminal is the primary canvas, with one compact control row outside its content, no visible branding header or footer, and no floating success messages. The comparison indicator sits in the control row only while comparing. Errors reopen the editor when necessary and stay inside it; dismissing or collapsing it clears the terminal view without silently discarding the error. Pending-edit warnings remain beside export controls. Privacy, simulation limitations and setup explanations are available in the editor, not persistent preview banners.

The non-modal editor floats on the left or right without resizing, dimming, or blurring the preview. It can be collapsed and reopened without losing edits. On narrow screens it remains usable as a bounded overlay; terminal scenes can be scrolled rather than shrinking text to illegibility. On short viewports the editor scrolls as a whole so diagnostics, pending edits and exports remain reachable, while the workspace fits the viewport without scrolling its control row away. Editor controls have their own stable colors, independent of the theme under construction.

## Editing and documents

- Original `omtheme` and `omtheme-darkice` presets; no third-party theme catalog. Fresh visits start with desktop OMTheme, synchronized with desktop commit `f2b6c7e`. Dark Ice stays a separate companion palette. Preset updates never overwrite remembered or imported work.
- All 21 theme colors, strict `#RRGGBB`, and a printable name of 1–64 Unicode code points.
- Configuration/theme schema version 1, targeting desktop commit `9d7b01e` (0.17.1-dev.0 baseline; latest published release v0.17.0). Supported optional configuration fields are preserved, including keybindings. Unknown fields are rejected, not silently removed.
- Configuration controls cover font family/size/line-height/ligatures, per-side padding, scrollback, close confirmation, logging, Option key behavior, Windows shell, keyboard shortcuts, and a JSON editor for the entire supported document including `theme.path`.
- The collapsible **Window & background** group covers all five window fields. `showTitleBar` and `showTabBar` default to true; `alwaysOnTop` and `blur` default to false; `transparency` defaults to 0 and accepts finite fractions from 0 through 1. Wrong types, unknown keys and out-of-range values are rejected, never clamped. Editing one field preserves every sibling and leaves omitted defaults implicit; merely focusing a numeric control does not add a default to JSON.
- Window settings update the simulation except always-on-top, which is explicitly export-only. Guidance distinguishes simulated browser effects from native behavior, and live background effects from new-window chrome/always-on-top defaults, the two-tab minimum for a visible tab bar, positive transparency needed for blur, and native platform limitations. In particular, Windows without blur stays opaque; Acrylic requires Windows 11 22H2 or later and can still fall back to opaque. Linux blur is best effort on X11, not native Wayland. macOS prefers direct blur with HUD fallback. No native visual result is certified by Studio.
- The collapsible shortcut editor covers all 27 supported actions (including `toggleTitleBar`) with readable labels, filtering, editable accelerator text, inherited target-platform defaults, and existing overrides. It does not capture or execute keystrokes. Apply validates the entire staged map at once, permitting binding swaps; discard restores the applied map. Per-action restoration removes the override rather than exporting a default-filled map. Invalid accelerator syntax and collisions with effective bindings block application. PTY control-key interception warns and keeps a valid explicit override, matching the desktop policy.
- Target changes recompute shortcut defaults and collision checks without rewriting explicit overrides. Staged shortcuts survive section changes and unrelated appearance updates; imports or JSON application refresh the shortcut draft when the applied keybindings change. Pending shortcuts disable JSON editing/application until applied or discarded. Pending full-document JSON disables the other configuration controls until applied or discarded, except the target selector. These drafts cannot silently overwrite one another.
- Local font family names use CSS with monospace fallback. There is no font enumeration, file access, or upload. The site cannot certify that a font or path exists, a shell is executable, or a native shortcut works. Platform-specific shortcut collisions are checked against the selected export platform. `windowsShell` remains a non-empty NUL-free string on every target; only Windows requires absolute Windows path syntax. Studio cannot perform the desktop's regular-file check and does not imply executable validation.
- Local JSON imports are bounded, decoded as strict UTF-8, and validated before replacing current state. Importing configuration never reads or fetches `theme.path`; the user imports the palette separately.
- Theme undo/redo and reference comparison are available. Preset changes and imports are deliberate editing actions, not destructive resets of the only copy.
- Switching editor sections preserves the selected color, incomplete theme text, and unapplied Configuration JSON/shortcut edits and their disclosure state. Inactive controls are hidden from keyboard and assistive navigation. Switching sections does not apply pending JSON, shortcuts, or invalid theme text.
- Unapplied JSON and shortcut edits are identified beside the export controls; downloads continue to use the last validated, applied configuration until explicit application succeeds. Invalid theme text blocks theme/pair downloads with a visible explanation, without blocking standalone configuration export.
- In-app setup guidance directs beginners to select a target, import existing preferences, apply pending edits, back up files, place the exported pair together in the configuration directory, and reload in OMXTerm. It explains standalone export choices, XDG/default folders, and settings that need new windows/tabs. Studio never installs files or reloads the desktop app.
- Download a theme JSON, the configuration JSON, or a paired ZIP. The paired ZIP explicitly uses `config.json` and `themes/theme.json`, replacing `theme.path` only in the exported copy; standalone configuration retains its selected path.
- No configuration data enters URLs, analytics, logs, or network requests. No imported content is executed. Draft persistence is opt-in and clearly labeled; unavailable/corrupt storage must not break editing. Only validated, applied documents are persisted. Unapplied JSON, shortcut edits, and invalid theme text remain in the current tab; a best-effort browser page-exit warning is requested for them even when persistence is enabled.

## Delivery

GitHub Pages serves built static files from a reviewed main branch. One documented check command runs formatting, lint, strict TypeScript, unit tests, and a production build. Browser tests verify core editing, import/export, overlay geometry, and responsive behavior. No application version bump, desktop artifact, or desktop-repository change is part of this workshop.
